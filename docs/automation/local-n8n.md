# Local n8n setup

On 26 October 2026, official n8n **2.44.6** was installed in the task workspace beside the repository (`work/n8n-runtime`). Its empty local database is in `work/private-n8n`, restricted to the local user. The owner account was set up by the user. No owner password, Gmail connection or provider credential was created by the assistant. The editor was started on **http://localhost:5678**, bound to **127.0.0.1**. This process is not a hosted service and stops when terminated or the computer sleeps/restarts.

The user completed owner setup. Do not give the assistant your password. Five prepared research workflows were imported through the official n8n CLI and verified through workflow export; all remain inactive and without configured credentials. Their coordinator has its four child IDs wired, with its connection gate disabled. Importing does not connect Life to n8n or grant mailbox/provider access. Any credential/connection scopes must be selected by the user. Do not expose this setup port to the internet.

To restart the installed runtime with the same local data, run `node automation/n8n/start-local.mjs` from the repository. The script expects the runtime beside this checkout; it installs nothing, creates no account and binds only to localhost. Use Ctrl+C to stop it. Use the current Node executable if `node` is not on the terminal PATH. The initial download used the bundled package manager; only the required official SQLite prebuilt binding was manually installed, rather than running every optional package build script.

Before background agents can run continuously, choose either a supported always-on self-hosted environment or a user-owned n8n Cloud workspace. Hosting cost and account setup were not authorised or purchased. Ramble in-app research uses the existing private Gemini configuration. The polling agent exports use a Gemini credential entered by the user in n8n; they do not extract the server key.

A real n8n-to-Life connection uses the scoped proposal bridge and review flow in `n8n-research.md`; owner approval and worker credentials are still required. Do not copy browser cookies, the owner's Life password or provider keys into webhook URLs. The worker can only claim public research jobs and submit proposals. It cannot directly change company/application/document records. Until the bridge and credentials are configured and an execution is verified, Life must report automation as **not connected**.
