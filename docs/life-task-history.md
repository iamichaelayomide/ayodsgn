# Permanent task history

History is a read-only card accessible from the main sidebar. It contains Completed, Blocked and Archived status entries, filters and incremental loading. “Done” and completed tasks use the same Completed category. Each entry preserves its original task snapshot, board/list labels and the time it was recorded. Changes to a live task do not edit old history.

Migration: `LifeStore` creates the account-scoped `life_task_history` table if missing, with unique tenant/event keys. Existing tasks currently completed, blocked or archived are seeded on the first history read or mutation. Earlier states that the previous app never retained cannot be reconstructed. Existing entries are marked with the `existing` source; their recorded timestamp is the migration time, not an invented historical completion date.

Mutations append status transitions inside the planner transaction. Failed multi-action transactions roll back new journal entries along with task writes. AI Undo restores mutable planner state while keeping previous committed history. Task, list and board archives preserve snapshots. History lives outside the mutable board JSON, so replacement of planner state cannot erase it. No update, clear or delete endpoint, UI control or AI operation is exposed. This guarantee applies to planner users and application operations; database administrators and catastrophic storage loss remain outside it. Normal production backups remain necessary.

Tenant ownership is enforced on reads. Partner access is excluded. Private ZIP backups include a full `task-history.json` export without the activity log's existing truncation limit. History is paginated in batches of 100, with no automatic retention cap. Account data is never combined.

Verification: dedicated isolated tests cover status capture, immutable titles, reopening, archives/restores, unknown delete actions, rollback, Undo, account isolation and mutable-state replacement. Existing command, voice, AI and account tests run against the same candidate. Browser preview checks visible filters and absence of deletion controls.
