# Task and goal history

History stores snapshots of completed, blocked and archived tasks, and completed or archived goals. Ordinary planner edits and AI Undo do not erase these records. The user revised the previous read-only requirement on 13 October 2026: History now supports search, reopening and explicitly confirmed permanent deletion of individual History records.

Search matches decoded titles, descriptions, blockers, board/list labels and goal categories, including Unicode and literal wildcard characters. Search runs before pagination; all matches remain accessible in batches of 100. Older task snapshots without a kind field remain compatible. Goal snapshots keep their original period and content. Migration creates `life_history_seed`, with account/kind markers so deleted records never reappear through initial seeding. Existing history is preserved; current eligible goals are seeded once. Earlier states that were never stored cannot be reconstructed.

Restore prompts for an active board/list for tasks, or a goal period and date. The server reopens the current record using its stable identity, preserving later edits. If the item is absent, it restores the saved snapshot. Task completion, blockers and approval are cleared; reminders require setting again. Goal completion and approval are cleared; goal links are detached, and periods cannot change while active child goals depend on them. Done-list destinations and archived or foreign destinations are rejected.

Permanent deletion removes only the chosen History snapshot. The confirmation states that it cannot be restored and the current planner item is kept. It does not remove other history events for the same item, the current planner record, or prior backup archives. History deletion is excluded from AI tools and is not an AI Undo operation. New future status transitions can create fresh entries. Deletion, restore and planner version changes run transactionally with existing owner/tenant checks, CSRF protection and stale-version rejection. Partners cannot access or mutate History.

Private backups include the remaining History entries. No automatic retention cap applies. The sidebar is sticky on desktop and its whole contents scroll independently within the viewport; mobile retains its independently scrollable drawer. Sidebar ribbons retain the softened overlay.
